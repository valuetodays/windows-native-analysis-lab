# Windows 用户态程序观察、分析和实验能力建设方案

## 1. 项目定位

项目名称：

Windows Native Analysis Lab

目标：

建立 Windows 用户态程序的观察、分析和实验能力。

本项目不是单纯学习 Win32 API，而是通过：

-   Windows API 知识地图
-   可控实验程序
-   x64dbg 动态分析
-   异常模拟
-   PE/DLL 分析

逐步建立理解、分析和扩展 Windows 程序的能力。

最终目标：

看到一个未知 EXE，可以分析：

-   它是什么类型程序
-   使用哪些 Windows 能力
-   调用了哪些关键 API
-   数据如何流动
-   为什么异常
-   如何进行扩展和改造

------------------------------------------------------------------------

# 2. 核心原则

## 原则 1：先观察，再分析，最后修改

学习路径：

    观察 Windows 程序行为

            ↓

    理解 API 和系统机制

            ↓

    定位问题和异常

            ↓

    修改和扩展程序

Hook、注入属于高级能力，不作为起点。

------------------------------------------------------------------------

## 原则 2：API 是工具，不是目标

不追求记住所有 Windows API。

重点：

按照真实软件行为分类：

-   程序启动
-   进程
-   线程
-   内存
-   文件
-   网络
-   窗口
-   DLL
-   异常
-   调试

建立：

    功能
     ↓
    相关 DLL
     ↓
    核心 API
     ↓
    真实使用场景
     ↓
    分析方法

------------------------------------------------------------------------

# 3. 第一阶段：Windows API Knowledge Map

目标：

建立 Windows API 功能知识地图。

第一版范围：

## 3.1 Process（进程）

关注：

程序如何创建、管理其它程序。

主要 DLL：

-   kernel32.dll
-   ntdll.dll

核心 API：

-   CreateProcess
-   OpenProcess
-   TerminateProcess
-   GetProcessId

实际场景：

-   启动器
-   多进程软件
-   客户端架构

------------------------------------------------------------------------

## 3.2 Thread（线程）

关注：

程序如何执行并发任务。

核心 API：

-   CreateThread
-   WaitForSingleObject
-   Sleep
-   Synchronization API

实际场景：

-   后台任务
-   网络线程
-   UI线程

------------------------------------------------------------------------

## 3.3 Memory（内存）

关注：

程序运行时如何管理内存。

核心 API：

-   VirtualAlloc
-   VirtualProtect
-   VirtualFree
-   HeapAlloc

实际场景：

-   动态对象
-   JIT
-   游戏数据
-   动态代码

------------------------------------------------------------------------

## 3.4 File System（文件）

关注：

程序如何访问文件。

核心 API：

-   CreateFile
-   ReadFile
-   WriteFile
-   FindFirstFile

实际场景：

-   配置文件
-   日志
-   数据文件

------------------------------------------------------------------------

## 3.5 DLL / Module

关注：

程序如何加载功能模块。

核心 API：

-   LoadLibrary
-   GetProcAddress
-   FreeLibrary

实际场景：

-   插件
-   动态加载
-   Hook 基础

------------------------------------------------------------------------

## 3.6 Window / GUI

关注：

Windows 图形程序运行方式。

相关 DLL：

-   user32.dll
-   gdi32.dll

核心 API：

-   CreateWindowEx
-   ShowWindow
-   SendMessage
-   GetMessage

------------------------------------------------------------------------

## 3.7 Network

关注：

程序如何通信。

相关 DLL：

-   ws2_32.dll
-   winhttp.dll

核心 API：

-   socket
-   connect
-   send
-   recv

------------------------------------------------------------------------

## 3.8 Registry / Security

关注：

程序与系统配置、权限。

相关 DLL：

-   advapi32.dll

核心 API：

-   RegOpenKey
-   RegQueryValue
-   OpenProcessToken

------------------------------------------------------------------------

## 3.9 Exception / Debug

关注：

程序为什么崩溃。

重点：

-   Access Violation
-   ExceptionCode
-   SEH
-   调用栈分析

------------------------------------------------------------------------

# 7. 第三阶段：异常实验室

目标：

模拟真实崩溃。

重点：

## Access Violation

ExceptionCode:

    c0000005

类型：

-   Read violation
-   Write violation
-   Execute violation

实验：

-   空指针访问
-   野指针
-   越界访问
-   执行不可执行内存

目标：

能够从异常信息定位：

-   哪个线程
-   哪个模块
-   哪个调用栈
-   哪种错误
